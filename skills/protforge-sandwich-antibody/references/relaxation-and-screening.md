# 松弛与筛选：配方与失效特征

## 受限松弛配方

### 约束施加顺序（错误代价极高）

```python
sim.minimizeEnergy(...)                              # 先最小化
sim.context.setVelocitiesToTemperature(T, seed)      # 再设速度
sim.step(MD_STEPS)                                   # 最后跑 MD
```

速度设在最小化**之前**时，每一个设计都发散成 NaN。最小化不清零积分器的
thermostat 状态。改回顺序后 42/42 恢复正常。

### 种子

```python
seed = BASE ^ (crc32(该设计自身的坐标记录) & 0x7FFFFFFF)
```

- **不设种子**：每个构象是一次随机抽样，判据在设计上不可复现。
- **全局固定种子**：更糟。每条设计拿到**完全相同**的速度分配，约 7100 个原子
  同向运动，系统性不稳定。
- **按设计派生**：可复现，且各设计独立。

种子必须来自设计**内容**（排序后的 ATOM/HETATM 行），不要哈希整个文件——文件名
或头部文本的差异会让同一条设计落到不同种子上。这条踩过：两次「同一设计」的测量
用了不同暂存文件名，seed 不同，结果差 0.3 Å，一度被误判成流程缺陷。

### NaN 防护

NaN 只在写结构文件时抛出来，也就是**整轮跑完才失败**；批量脚本若在循环之后写盘，
这一批全丢。

```python
pre_md = sim.context.getState(getPositions=True).getPositions(asNumpy=True)
try:
    sim.context.setVelocitiesToTemperature(300*unit.kelvin, seed)
    sim.step(MD_STEPS)
    if not np.isfinite(final_positions).all():
        raise ValueError("non-finite coordinates")
except Exception:
    sim.context.setPositions(pre_md)   # 回退到最小化构象
    md_ok = False                      # 显式标注 no MD
```

MD 是精修不是测量。发散时保留最小化构象并标注，比丢掉整个设计好。

### 可复现性的真实精度：必须实测，不能从种子派生推断

GPU 归约不是逐位确定的。**实测**：同一份输入文件、同一颗速度种子，重建 3 次，
最小重原子距离散布 **0.24 Å**（捕获 2.97 / 2.80 / 3.04；检测 2.68 / 2.78 / 2.54）。
无种子时散布 0.2–0.4 Å。

**规则**：可复现性只能靠 `repro_check.py` 这类「同输入同种子重复 N 次」的脚本测出来，
**不能因为种子是内容派生的（`seed_base XOR CRC32(排序后 ATOM 行)`）就断言可复现**。
本技能早期版本写的是「可复现到 ~0.02 Å」，那是从种子派生方式**推出来的**，从没测过，
实测是错的——而它已经进了交付文件。

写交付时：说「固定种子下不可复现，N 次重复散布 X Å」，不要写「可复现」，
也不要写任何没测过的精度数字。

### 交付构象必须是它自己那份分布里的一个成员

交付的 PDB 与记录的构象分布**必须出自同一批松弛**。两批抽样会让交付值落到
记录区间之外（本例：交付 2.94 Å vs 记录 2.73–2.88 Å），交付自相矛盾，
比数值难看严重得多。

选交付构象的规则要在**测量前**定死：

| 规则 | 后果 |
|---|---|
| 交付调度器随机产出的那一个 | 等于抽样，会抽到最差构象（本例 2.51 Å 且触及埋藏面残基 50） |
| 4 个种子按最小距离排序取**中位数** | 预先声明、不朝判据凑；分布与交付同批 |

自检：`delivered_value in recorded_values`。「落在区间内」是不够的——
本例中这个较弱的检查曾经放过一次真正的不一致。

## 多种子判据

任何距离类判据都必须多种子评估：

```python
vals = [measure(seed_base=BASE + 1000*k) for k in range(n)]
report = {"min": min(vals), "median": median(vals), "max": max(vals),
          "clears": f"{sum(clears)}/{n}"}
```

**1/4 构象过线 ≠ 过线。** 把结论记成 shortfall，不要引用那个好的抽样。

判据结论字段用两种，不要混：

- `FAIL`：声明与数据矛盾 → 改流水线（重算值 ≠ 记录值、序列与坐标不符）
- `GAP`：真实局限 → 披露（未达阈值、某构象触及埋藏面）

### 判据检查要验「数据一致性」，不要验字符串相等

```python
# 错：verdict 换个正确说法就判 FAIL，而交付本身是对的
ck(verdict == "not met on most conformers", ...)

# 对：从逐种子数据推出应有结论，再比对
n_clear = sum(1 for v, p in zip(vals, pairs) if v >= 3.0 and p == 0)
ck(verdict == ("ROBUSTLY MET" if n_clear == n else "NOT ROBUSTLY MET"), ...)
```

判据未达本身走 `GAP`，不走 `FAIL`；`FAIL` 留给「verdict 与自己的数据矛盾」。

## 按几何排序候选

骨架被刚体对接冻结 ⇒ **哪些 CDR 位点贴着抗原是位姿属性、与设计无关**；只有
贴上去的侧链因设计而异。

```python
contact_pos = {ch: [i for i in CDR[ch]
                    if min_dist(pose_backbone[ch][i], antigen) < 8.0]}
bulk = sum(SC_HEAVY[design[ch][i-1]] for ch in contact_pos for i in contact_pos[ch])
# 按 bulk 升序送去做松弛
```

**不要按模型序列分数排序。** 实测：检测位姿下，MPNN 分数前 6 名里有 2 名是
128 条里接触面最臃肿的，6/6 全部未过线；换成体积排序后 79 条中 16 条过线。

## 三元复合物无约束 MD：唯一能回答「刚体假设是否成立」的实验

单 Fv 的受限松弛无法回答两个问题：夹心几何是不是刚体假设的产物？紧密堆积是不是
约束造成的假象？两者都只能靠**三元复合物 + 零约束动力学**回答。

```
组装：由两份交付结构构建（不要用对接上下文，见下），伙伴 Fv 用抗原链做 Kabsch
      叠合；组装后必须 pre-flight——从组装文件重算距离，应复现交付数字
stage 1：仅骨架约束的最小化，清理 2.8 Å 初始接触
stage 2：移除全部约束 + context.reinitialize(preserveState=True)，然后
      300 K / 2 fs 动力学，全程零位置约束
采样：每 5 ps 记 cap-ag、det-ag、Fv-Fv 的最小重原子距离与 <3 Å 对数
```

**实测结论（本项目）**：Fv–Fv 从约束下的 12.58 Å 变为中位 12.77 Å、全程最小
8.70 Å → **夹心几何成立，12.58 Å 不是刚体产物**。但 cap-ag 中位 2.82 Å（约束下
2.84）、det-ag 2.72 Å（约束下 2.76）→ **过度堆积不是约束的假象，是配准本身的
属性**。

> **因此「紧密堆积的根因是骨架被冻住」这个常见说法要慎用**。骨架确实在动，但 CDR
> 仍停在对接的配准上，接触距离不变。正确的结论是「换序列救不了错的配准」，
> 而不是「放开 MD 就能缓解」。这个归因错误很容易一路传到最终报告里。

### 三个会毁掉一次运行的坑

1. **`addForce` 必须在 `Simulation(...)` 之前**。之后加的力不进已建好的 Context，
   于是最小化实际无约束，2.8 Å 的接触被撕开。移除约束后必须显式
   `sim.context.reinitialize(preserveState=True)`。
2. **OpenMM 位置是 nanometer**。把它当 Å 读会把 0.28 nm（= 2.8 Å）看成 0.28 Å 的
   碰撞，`d < 3.0` 阈值实际变成 30 Å 从而数出几十万个「重叠对」——一个纯粹的单位
   错误看起来像灾难性的物理失败，差点让人去改本来正确的代码。
   **每处距离输出与阈值都显式乘 `NM_TO_A`**，并在跑之前用独立路径（gemmi）核对一次。
3. **组装要用交付结构，不要用对接上下文**。用 gemmi 克隆上下文链会丢重原子，
   pdbfixer 随后按猜测位置补侧链，补出假碰撞。交付结构完整（pdbfixer 补 0 个原子）。
   无论用哪个输入，**组装后都要 pre-flight：距离明显不对就中止**，别让坏输入伪装
   成物理结果。

### 这项验证能说和不能说的

能说：界面不散、不碰撞、夹心几何成立。不能说：收敛到了某个结合模式。
200 ps + 隐式溶剂不足以收敛，且轨迹从交付构象出发，**没有采样替代配准**，
所以不能排除存在更受偏好的结合模式。

## 独立表位交叉验证：必须失败模式不同，且要照实报不对称结果

用 **DiscoTope-3.0**（ESM-IF1 逆折叠表位倾向）。选它的唯一理由：它只看结构、
抗体不在场、不做对接，失效模式与刚体对接无关。

**两种模式都要跑，以二聚体模式为主**：自由单体会暴露天然二聚体里埋藏的残基，
因而系统性过预测（实测单体模式判出的表位里 17/39 是埋藏残基；二聚体模式仍有
10 个）。裁判自己会犯这类错，所以它只能当弱证据，不能当硬过滤器。

**做法**：拿交付表位残基的平均 calibrated score，对比**暴露表面基线**（剔除埋藏
残基后的同链均值），而不是看绝对值或「排在第几位」。

**结果必须照实报，即使不对称。** 本项目实测：检测表位 +0.410（获支持），
捕获表位 +0.067（未获支持）——而捕获本就是界面较小的一侧（544 vs 942 Å²）。

### ⚠️ 交叉验证「独立」到什么程度，要说准

**DiscoTope-3.0 是抗体不可知的**：它只看结构、抗体不在场、不做对接。所以它
**独立于抗体序列，但并不独立于位姿**——它根本看不到位姿，无法确认「这条抗体
是否结合这里」。

> 「捕获未获支持」的正确解读是：**该位姿给出的残基区域，在二聚体表面上看起来
> 不像高表位倾向的 B 细胞表位区**。这是**强警示，不是判决**。
>
> 写成「两个互相独立的指标都说捕获弱」是错的：BSA 来自位姿，DT3 来自结构，
> 二者共享「位姿选了这个区域」这个前提。

**要真正打破位姿单源依赖**，需要**抗体条件化**的表位预测（ParaSurf / AbEpiTope
一类）再与位姿表位比对。本机无可商用的此类工具：ParaSurf 容器未安装、AbEpiTope
经核实不是表位预测器、tFold-Ag 为 PolyForm 非商用。**这层依赖只能披露，不能假装
已经交叉验证过。**

**看逐残基分数，不要只看均值。** 实测捕获表位逐残基为 23: 0.35、26: 0.67、
**38: −0.82**、39: 0.19、40: 0.19、41: 1.14、**48: 2.00**——低分集中在 38/39/40，
**不在界面附近**，说明「二聚体埋藏解释低分」的假设是错的；真正的解释是残基 38
自身在游离单体里相对 SASA 就只有 0.038。**均值会把这种结构完全抹掉。**

## 本管线中已验证废弃的路线

- **RFdiffusion 无热点引导势**：本机构建里 `ppi.hotspot_res` 在
  `potentials/manager.py` 算出后从未被使用，于是整条抗体链被重摆，界面 BSA 只有
  170–480 Å²。用它之前先确认热点势真的接进去了（见 `protforge-rfdiffusion`）。
- **IgFold 重新预测 Fv 结构**：手上已有支架晶体结构时是纯粹的信息损失。
- **DiffDock 类 Ab-Ag 对接**：成功率低，产出应是多个候选位姿而不是判决。
- **MM-GBSA / PRODIGY 当排序指标**：绝对值对 Ab-Ag 不可靠；两个候选界面差
  0.2 Å 量级时，方法噪声远大于信号，会制造虚假精度感。
  ——但**这个拒绝只对噪声量级的差异成立**：捕获 544 Å² vs 检测 942 Å² 是 400 Å²
  量级，不在噪声内，不能用同一句话一并拒绝掉。
