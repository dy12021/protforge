# 抗体结构不变式（可机检的那些）

只收录**能写成断言**的不变式。凡是需要"看情况"的，进文末 commentary 区。

## 1. 保守二硫键网络

| 键 | 位置（Chothia/Kabat VH-VL 编号） | 说明 |
|---|---|---|
| VH 域内 | **Cys22 – Cys96** | Cys96 是 CDR-H3 的第一个残基 |
| VL 域内 | **Cys23 – Cys88** | Cys88 是 CDR-L3 的第一个残基 |
| VL–VH 链间 | VL Cys – CH1 Cys | 完整 IgG 中连接重轻链 |

**断言方式**：把交付序列与**父本支架**的 Cys 位置列出来，逐链比较。

```
parent   VH Cys: [22, 95/96]     <- 95/96 就是保守的那个
delivered VH Cys: 必须仍然包含 [22, 95/96]
```

**这个断言抓到过真缺陷。** 交付的 VH 只剩 Cys22，域内二硫键的一半没了；而当时的
检查项写的是「CDR 内无半胱氨酸 → 通过」——它在检查一个**代理**，代理绿的时候
目标已经坏了。删掉保守 Cys 反而让"CDR 内无半胱氨酸"这条更干净。

**不要用 `--omit_AAs C` 这类全局禁用。** 它的意图是防杂散二硫键，副作用是连
保守位点一起删。正确做法：把保守位点放进 `fixed_positions` 钉死，其余可设计
位点仍然禁 C。

**断言必须写成「恰好这两个 Cys」，不是「CDR 内无 Cys」。**

写成后者会得到一个**把缺陷当不变式**的检查：Cys96 就是 CDR-H3 的第一个残基，
所以任何正确的抗体都必然在 CDR 里有一个 Cys。本技能的第一版检查项正是
「CDR 内无半胱氨酸」，它在缺陷版本上绿、在修好之后红——检查项本身错了。

```python
ACCEPT = {"VH": ({22, 96}, {22, 95}),   # 两个母本在铰链区差一个残基
          "VL": ({23, 88},)}
for nm, s in (("VH", vh), ("VL", vl)):
    pos = {i + 1 for i, c in enumerate(s) if c == "C"}
    ck(pos in ACCEPT[nm], f"{nm}: cysteines {sorted(pos)}")
```

要抓的缺陷是**多出来的** Cys（可错配、可成链间二硫键），不是那个正确的保守位点。

## 2. CDR 定义与编号

同一套序列在 Chothia / Kabat / IMGT 下边界不同，**说清楚用哪套**。

- 本项目用 Kabat 风格的输入支架边界：H 26-35 / 50-65 / 95-102，L 24-34 /
  50-56 / 89-97。
- CDR-H2 = 16 残基、L2 = 7 残基在 Kabat 下是**正常的**。用 IMGT/Chothia 的
  8-12 / 3-5 去判会得到一堆假的「超范围」——这条误报过一次。

**断言方式**：声明的 CDR 序列 == 按声明区间从序列切出的子串。

## 3. 框架保真

嫁接 CDR 的设计，框架必须 100% 等于父本支架。逐位比对并报告不匹配数，不要只
报布尔值。

## 4. 糖基化 sequon

`N[^P][ST]`，位于 CDR 内即是风险；位于抗原接触环上尤其严重（糖链占据结合面）。
`protforge-reglyco` 可以做完整分析，但**纯序列扫描就能发现它**，成本是秒级。

**断言方式**：扫交付 VH/VL，报告每个 CDR 内的命中位置。

**注意设计器与约束的冲突**：如果采样在某位点上 100% 选 N（而 N+[ST] 必然成
sequon），输出过滤会把整个设计集丢掉。此时**把该位点钉回父本残基**并重跑设计
器，而不是接受过滤。实测 CDR-L2 的位置 50 出现过 128/128 全部成 sequon。

## 5. 标准残基

ProteinMPNN 的字母表含 `X`。含 `X` 的设计能通过长度、框架保真、结构回写等
**所有**其他检查，只在真正下单合成时暴露；它还会让批量跑到一半崩在
`KeyError`，连带丢掉同批次已完成的结果。

**断言方式**：`set(seq) <= set("ACDEFGHIKLMNPQRSTVWY")`，对 VH/VL/重链/轻链
四者都做。

## 6. VH–VL 界面（配对保真）

VH/VL 界面的成对残基（VH Val49/Met57 ↔ VL Phe 等）是 VH-VL 配对的主要能量来源。
本管线下两条抗体的框架 100% 取自真实支架（1VFB、1NCA），配对**继承自晶体结构**——
不需要预测，只需要确认没被嫁接的 CDR 破坏。

真正的风险很窄：CDR-H3 和 CDR-L1 位于 H–L 界面上，重设计的侧链可能把两个
结构域撑开。

**断言方式**（不是绝对阈值，是**相对父本支架的保持率**）：

1. 在交付 Fv 与父本支架上分别算 VH↔VL 接触原子对数（cutoff 5 Å）与 H–L
   界面 BSA（FreeSASA：两条链各自的总 SASA 减去复合物的 SASA）。
2. 报告 `delivered / parent` 两个比值，**不要只报布尔值**。
3. 列出所有「在父本里是 H–L 界面残基、在交付里落在 CDR 内」的残基，逐个看它
   的侧链是否还朝向另一条链。

```
parent   H-L contacts 214   BSA 812 A^2
delivered H-L contacts 198   BSA 764 A^2   ratio 0.93 / 0.94   -> 保持
delivered H-L contacts 151   BSA 585 A^2   ratio 0.71 / 0.72   -> 松了，别放过
```

**为什么是保持率而不是绝对阈值**：不同支架的 H–L 界面天然大小不同，套一个
绝对数字必然要么全过要么全挂。真正会出事的是**相对自己父本的塌陷**。

**换支架或做界面工程时这条必须重跑。** 保守残基留着不等于界面还在——VH
Trp52 还在，不代表它还压着 VL 的 Phe。

**不要用配对预测模型做这件事。** 候选模型（p-AbNatiV2、ImmunoMatch）都是
非商用许可，OpenGerminal 虽是 Apache 2.0 但只做 VHH 设计没有配对输出。见
`license-registry.md`。这是个免费的断言，不值得为它引入一个许可证受限的依赖。


## Commentary（不要写成断言）

- 芳香环含量、非特异结合倾向、聚集风险：值得记录，但不是二值判据。
  聚反应性已经有专门的序列级模型（`protforge-polyxpert`），比人工数芳香环靠谱，
  但**它同样没有上游阈值**——见下面「不要写成断言」的理由。
- **ESM-2 困惑度（`protforge-esm`）**：10 残基环上主要由环长和氨基酸频率支配，
  对「抗体样性」判别力弱。抓不到上面任何一条不变式的破坏。
- 溶解度模型：`protforge-chemprop` 面向小分子，对抗体不适用。
- **免疫原性（MHC-II、T 细胞表位）不在本管线的范围内。** 那套指标针对的是
  抗体被注入人体的场景；检测试剂盒里的抗体不进人体，免疫原性对它没有决策意义。
  把它当质控项是指标错配。对试剂盒真正有意义的是背景信号，也就是聚反应性。
